# Boilerplate v1.1.0 release candidate

Release axis: boilerplate

Publication status: PLANNED; this source candidate does not create a tag,
GitHub Release, archive, signature, or downstream adoption

Catalog contracts: core-v1 and index-v2

Profiles: bootstrap, standard (default and legacy), and scaled remain supported

Manifest and provider contracts: manifest-v1 remains supported;
manifest-v2 supports optional components; manifest-v3 requires the explicit
single-path ownership handoff in soku/v0.3.0; provider-v1 remains supported

Compatible soku: soku/v0.3.0 (candidate; official distribution pending)

Migration from previous release: v1.0.5 to v1.1.0 replaces the legacy CI
with separate Quick, Full Validation, and Security workflows, adds the two
new workflow paths, refreshes the JS development dependencies/lockfile and
shared mergeable gitignore, and preserves existing selection and ownership rules

Provider compatibility: provider-v1 unchanged; optional deprecated legacy ref
behavior remains supported; no provider, Project Sync, or delivery activation
is implied by a core upgrade

Companion tag: soku/v0.3.0

The companion tag is proposed; neither tag has been created.

The JavaScript/TypeScript/Node Full Validation job now executes in the
downstream checkout root, where the generated package and source files live.
It retains npm ci, lint, typecheck, test, build, and format checks on Node 22.
Quick already runs at the root; its pull-request/main-push contract remains
separate from scheduled/manual Full Validation and Security. Boilerplate's
own template validation continues to use templates/javascript-typescript-node.

Existing v1/v2 manifests are not implicitly migrated to v3 by an upgrade.
Only a reviewed, intentionally modified core-managed file can be transferred
with an exact normalized SHA-256. Each handoff changes the manifest only,
preserves file bytes/mode, and suppresses future core rendering for that path.
Old clients cannot mutate v3 state; choose the compatible CLI before handoff.

The local Control Center rehearsal is fixture evidence, with a synthetic
target commit; it does not resolve an official release or update the actual
downstream manifest. Full repository, runtime-template, security, sync parity,
quality/race, package reproducibility, three-OS lifecycle, exact candidate
hosted checks, and public immutable-release migration remain release gates.
Any missing gate must remain NOT_VERIFIED. Published tags and historical
release records remain immutable.

The isolated source candidate aligns release-identity.json and all derived
distribution surfaces on these proposed versions without claiming publication.
Before delivery, obtain independent review and human approval for signing/
release operations after all required gates, and record the actual source
commit. No candidate commit, published-release identity, signature, or approval
is inferred here.
