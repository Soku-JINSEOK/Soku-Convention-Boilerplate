# Boilerplate v1.1.1 release candidate

Release axis: boilerplate

Publication status: unpublished recovery candidate; a new signing/release
decision is required after exact-source validation

Catalog contracts: core-v1 and index-v2

Profiles: bootstrap, standard (default and legacy), and scaled

Manifest and provider contracts: manifest-v1/v2 remain supported; manifest-v3
requires the explicit ownership handoff in the compatible CLI

Compatible soku: soku/v0.3.1 (candidate; distribution pending)

Migration from previous release: v1.0.5 to v1.1.1 carries the split Quick,
Full Validation and Security workflows, JS dependencies and mergeable gitignore
prepared for v1.1.0; existing selection and ownership contracts are preserved

Provider compatibility: provider-v1 unchanged; no provider or delivery
activation is implied by the core upgrade

Companion tag: soku/v0.3.1

The public tags `v1.1.0` and `soku/v0.3.0` are immutable and remain at
`772ed6f7aa165da1bbdef89a3129b7703dc5a029`. Their actual tag runs failed
because validation treated the all-zero previous revision of a new tag as a
commit. GitHub Release and npm publication were skipped. This candidate keeps
those records and advances both affected axes to new patch versions.

The repository validation caller now excludes the zero SHA when choosing the
Quick and Security base. It preserves trusted PR bases and existing branch
history. All required full gates, signing checks and publication conditions
remain in place. Downstream template content and ownership semantics are
unchanged from the v1.1.0 source candidate.

The corrected event selection has local regression coverage for real tag-event
shapes, including an annotated Git tag and actual scope/planner execution.
Exact-source hosted checks, signed tag delivery, official packages and actual
downstream adoption remain separate verification steps. No fixture is evidence
of completed public delivery.
